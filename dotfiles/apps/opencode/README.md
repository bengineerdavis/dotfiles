# opencode

Installs [opencode](https://github.com/anomalyco/opencode), the terminal AI
coding agent, and declares the machine's cross-agent skill set.

## What it manages

| Layer    | State                                              | Owner     |
|----------|----------------------------------------------------|-----------|
| Ansible  | the `opencode` binary, from the pinned tap          | this topic |
| Ansible  | the skill set in `~/.agents/skills`, via dotagents  | this topic |
| chezmoi  | `~/.config/opencode/opencode.jsonc`                 | `dot_config/opencode/` in the chezmoi source |
| nobody   | `~/.config/opencode/auth.json`, `opencode.db`, `node_modules` | machine-local, never versioned |

Layering: Ansible installs and triggers; chezmoi owns the config file; the
binary's own state (`auth.json` tokens, `opencode.db` session history) is
machine-local and no topic touches it on install or remove.

## The binary

Installed from `anomalyco/tap`, named explicitly
(`anomalyco/tap/opencode`) because homebrew/core carries a formula of the
same name and the two are different builds. This machine runs the tap build.

Darwin uses the homebrew topic. Debian resolves `homebrew` through the PATH
check — this box runs linuxbrew, and a fresh Debian box needs linuxbrew
installed before this topic can run. The install task fails with that named
fix if brew is absent.

## The skill set

`defaults/main.yaml` is the manifest. Each entry becomes one
`dotagents add <source> <name>` — user-global, into `~/.agents/skills` — which
opencode, claude, cursor and the other supported agents all auto-load. The
skills are shared infrastructure: every agent on the machine sees them, which
is also why `--tags remove` keeps them unless `opencode_remove_skills` is
flipped.

- Re-running the add refreshes the installation, so install is idempotent.
- `--tags upgrade` re-runs the sync; bumping the manifest is the whole
  upgrade procedure for skills.
- `interaction-questioning` requires the ai-prompt-library repo pushed past
  commit `94a3156` (2026-09-12), the one that moved it to
  `skills/interaction-questioning/`. Until then that entry fails discovery —
  the other four resolve regardless.

`~/.agents/agents.toml` records what was declared. It is generated by
dotagents and left machine-local: the manifest in this topic is the source of
truth, and re-running install reproduces the file anywhere.

## The config

`~/.config/opencode/opencode.jsonc` deploys from
`dot_config/opencode/opencode.jsonc` and carries the cross-machine baseline:
privacy (`share: disabled`), model defaults, and permission rules. Per-machine
choices (auth, per-project overrides) stay out of it. Measured on 2026-09-12:
when both `opencode.json` and `opencode.jsonc` exist, jsonc wins, so the
chezmoi-managed file is authoritative.

## Teardown

`--tags remove` uninstalls the binary. Two states are guarded behind flags
that default to false — flip them deliberately:

- `opencode_remove_tap` — untap `anomalyco/tap`
- `opencode_remove_skills` — `dotagents remove` each manifest skill

```bash
ansible-playbook apps/opencode/playbook.yaml --tags remove
ansible-playbook apps/opencode/playbook.yaml --tags remove \
  -e opencode_remove_skills=true -e opencode_remove_tap=true
```

## First run on a new machine

1. Provision chezmoi (deploys the config) and mise (provides node).
2. `./run-role.sh opencode` — or the parent playbook with `--tags provision`.
3. `opencode auth login` — tokens are machine-local by design.
