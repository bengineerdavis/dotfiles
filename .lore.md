* **check\_suite\_baseline.py gates CI on failing node ids, not pytest exit**: The dotfiles CI test job is judged by scripts/check\_suite\_baseline.py, which compares failing test node ids against a known-failure baseline — NOT pytest's exit status. Twelve known failures make bare pytest exit nonzero, so a job keyed on exit code would be 'either always red or silenced with || true'. The compare step must read the captured log ('judging a log never written is the silent-pass shape this repo keeps hitting'); tests/scripts/test\_ci\_workflow.py pins these properties. Consequence: a test that SKIPS vanishes from the baseline comparison, so the gate reads green while testing nothing — missing-dependency guards in this repo must FAIL in CI (os.environ.get('CI')) and only skip locally. Why skip looks right: it's pytest's normal missing-dependency idiom; here the baseline gate turns it into silent coverage loss.
