### Architecture

<!-- lore:01a18637-83e2-759f-ba94-5b00d66fa0a6 -->
* **Ansible remove tag: never implicit — bare run is provision-only**: Uninstalling is always a deliberate \`--tags remove\`; remove tasks are tagged \`never\`, so a bare (untagged) run does provision only and can never tear a topic down — new topics inherit this from template\_dir. Always scope real runs with a tag (\`--tags install\` is the common one). Tag semantics (docs/ARCHITECTURE.md): provision = bootstrap+prerequisites+upgrade+install; bootstrap = first-time system-tool setup (never silent); prerequisites = core deps (git/curl/xcode-cli); upgrade = system-level refresh only; install = topic packages; remove = teardown, explicit only. Topic tag hierarchy: pkg-manager (apt/homebrew/docker) → runtime-manager (mise/ollama) → app (everything else).

* **dotfiles/ is chezmoi source — runtime executes deployed tree, never the repo**: Author directive (2026-09-19): 'anything put here is then copied into the environment. nothing is run directly from this repository.' The repo is chezmoi SOURCE; the deployed tree executes — ansible via run-role.sh from ~/dotfiles, bin/ scripts from ~/bin. Layout since the docs-relocate series (2026-10-28): payload under \`home/\` via \`.chezmoiroot\`; docs/ merged to root \`docs/\` and is REPO-ONLY (never deploys — 2026-10-03 author ruling); repo-root tooling (tests/, scripts/) sits outside the source state automatically, so home/.chezmoiignore keeps only payload-specific ignores. Two proofs, neither substitutes: ansible-playbook --syntax-check validates SOURCE; converge/idempotence validates DEPLOYED after chezmoi apply (agents never run apply). The deployed tree cannot be branched (motivates AGENTS.md § Everything is branched): two agents applying from two branches overwrite each other; apply from main only, by the author or the main-checkout session. Motivating incident: 20 days of uncaptured work in aliases.zsh.

* **loreai playbook import order: prompts.yaml → service.yaml → agents.yaml is load-bearing**: In the loreai topic playbook, the service import sits AFTER prompts.yaml and BEFORE agents.yaml — the order is load-bearing, not cosmetic: the systemd/launchd unit sources its env file, so prompts must render first; agents.yaml points agents at the gateway, so the gateway must exist before agents configure against it. * **Provisioning installs and triggers, never contains logic or state (placement principle)**: Repo placement principle (AGENTS.md): provisioning may install and trigger a tool but NEVER contain its logic or state — logic and state live in the tool's own managed config or the deployed tree. Companion verification principle: a mechanism that can decline is proven to relent (the governance-deployment tests prove ignore rules didn't swallow real dotfiles). * **restart-stale: ctime not mtime; exact comm match; never SIGKILL**: dotfiles/roles/restart-stale answers 'is the running process older than its binary?' with one inequality: process start < binary ctime. Rejected alternatives (author walkthrough 2026-10-03): mtime/birthtime — Homebrew bottles carry archive-internal dates (ollama installed Sep 22 reports mtime Sep 18), so they miss real installs; ctime is kernel-set on write-into-place, cannot travel in an archive, and is safe-when-wrong (false positive = cheap restart; false negative = old code silently). Prefix/bundle process match — post-update-spawned helpers would answer for the app; match is exact full-path comm. Dropping unparseable ps rows — unknown ≠ not-running; ps\_rows raises. SIGKILL — never; GUI quit is a negotiation (osascript quit with timeout → poll ps → reopen derived bundle only after confirmed exit). Bare systemctl --user — needs XDG\_RUNTIME\_DIR; use the systemd module. Per-topic notify handlers — the upgrade event dies inside the one-concern-per-topic boundary; the state-based check needs no coupling, so topics append one check at end of install (ollama, 1password). Style standard: \[\[01a18498-a8f8-771d-bbbf-e6933fccb9a1]].
