* **topic-resolution requires\_map: teardown-safety index consumed by remove.yaml**: roles/topic-resolution emits requires\_map (dep → every topic requiring it) beside provides\_map; they answer different questions: provides\_map is 'who installs X' (install ordering); requires\_map is 'who NEEDS X' — the teardown question, because uninstalling a shared package for one topic silently breaks every other topic depending on it. remove.yaml consults requires\_map before tearing down anything it did not exclusively own. Built from ALL topics' metadata (resolution\_topic\_metadata, not just topics\_in\_run) so a not-run topic's claim still protects its dep; a '\[shared-dep]' debug report names multi-consumer deps. Fail-safe mechanics (docs/TOPICS.md): run-role.sh standalone runs skip the parent's pre\_tasks, so requires\_map is undefined there — undefined means UNPROVEN, not unshared: skip the removal. The index can't see hand-installs, so teardown is opt-in via \`\<topic>\_remove\_\<dep>\` default false. Companion trap: \[\[01a1b7bc-0182-7a89-8024-0c5233ad5265]].
