## Long-term Knowledge

### Architecture

<!-- lore:01a18637-83e2-759f-ba94-5b00d66fa0a6 -->
* **Ansible remove tag: never implicit — bare run is provision-only**: Uninstalling is always a deliberate \`--tags remove\`; remove tasks are tagged \`never\`, so a bare (untagged) run does provision only and can never tear a topic down — new topics inherit this from template\_dir. Always scope real runs with a tag (\`--tags install\` is the common one). Tag semantics (docs/ARCHITECTURE.md): provision = bootstrap+prerequisites+upgrade+install; bootstrap = first-time system-tool setup (never silent); prerequisites = core deps (git/curl/xcode-cli); upgrade = system-level refresh only; install = topic packages; remove = teardown, explicit only. Topic tag hierarchy: pkg-manager (apt/homebrew/docker) → runtime-manager (mise/ollama) → app (everything else).

* **Lima molecule delegation: Mac host owns VM lifecycle; guest is tested environment**: PR #99 (DOT-263) delegation model — flagged by the author as not obvious from code: Lima, Molecule, and Ansible all run on the Mac host; the Linux guest is the isolated environment being created and tested, never the controller of its own creation. 'Delegated' means the host asks Lima to manage the VM — a guest-owns-everything design would require the guest to create and manage nested VMs. Evidence splits by side: guest-side proof is Debian 12.15, aarch64, QEMU, running systemd user manager; host-side proof is the Molecule sequence (create→converge→idempotence→side\_effect→verify→cleanup→destroy) executed on macOS. Wording trap: 'only macOS was executed' means the controller/host was macOS — the guest was Linux. Instance name stays short (lima-mol) because Lima's SSH socket path (hash+name+suffix) must stay under the socket length limit.

* **restart-stale: ctime not mtime; exact comm match; never SIGKILL**: dotfiles/roles/restart-stale answers 'is the running process older than its binary?' with one inequality: process start < binary ctime. Rejected alternatives (author walkthrough 2026-10-03): mtime/birthtime — Homebrew bottles carry archive-internal dates (ollama installed Sep 22 reports mtime Sep 18), so they miss real installs; ctime is kernel-set on write-into-place, cannot travel in an archive, and is safe-when-wrong (false positive = cheap restart; false negative = old code silently). Prefix/bundle process match — post-update-spawned helpers would answer for the app; match is exact full-path comm. Dropping unparseable ps rows — unknown ≠ not-running; ps\_rows raises. SIGKILL — never; GUI quit is a negotiation (osascript quit with timeout → poll ps → reopen derived bundle only after confirmed exit). Bare systemctl --user — needs XDG\_RUNTIME\_DIR; use the systemd module. Per-topic notify handlers — the upgrade event dies inside the one-concern-per-topic boundary; the state-based check needs no coupling, so topics append one check at end of install (ollama, 1password). Style standard: \[\[01a18498-a8f8-771d-bbbf-e6933fccb9a1]].
