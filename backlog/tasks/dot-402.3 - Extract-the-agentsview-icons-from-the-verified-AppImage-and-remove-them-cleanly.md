## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The AppImage carries `agentsview-desktop.png` at 32×32, 128×128 and 256×256
under `usr/share/icons/hicolor/`. Register them so the launcher entry from
DOT-402.2 shows an icon instead of a generic placeholder.

Ship:

- Extraction from the AppImage the topic already downloaded and verified by
  SHA256 — using the AppImage's own `--appimage-extract`, which needs no
  FUSE (`unsquashfs` is not a dependency; verified 2026-11-24).
- Removal of any previously extracted set **before** writing the new one, so
  a version bump that renames an icon cannot leave stale files behind.
- Files written to `~/.local/share/icons/hicolor/{32x32,128x128,256x256}/apps/agentsview-desktop.png`
  at mode 0644.
- `gtk-update-icon-cache` where a cache exists, and no failure when it does
  not.
- `remove.yaml` deleting the three icon files.
- README stating that visual appearance in a live desktop session is
  **unverified**, with the reason (no GUI harness), so nobody reads the
  tests as proof the icon renders.

Constraints:

- Only extract from the verified AppImage. Never unpack an unverified
  artifact.
- Extraction is idempotent: two install runs leave exactly three icon files.
- Respect the `agentsview_install_desktop_appimage` opt-out.
- `~/.agentsview` untouched by both directions.

Tests (in the harness from DOT-402.1): the three files exist with mode 0644
after install; a second install leaves the count unchanged; remove deletes
them; the opt-out creates none. Skip with a named reason when the AppImage
or `desktop-file-validate` is absent.
<!-- SECTION:DESCRIPTION:END -->
