## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
The AppImage ships a `.desktop` file with a relative `Exec=agentsview-desktop`
and an empty `Categories=`, so it cannot be copied verbatim: the path does not
resolve outside the AppImage and the entry lands in no app-grid section.

Ship a template in the topic and wire it through install and remove:

- `templates/AgentsView.desktop.j2` rendering an absolute
  `Exec={{ agentsview_appimage_path }}`, `Categories=Utility`, and
  `MimeType=x-scheme-handler/agentsview` carried but **not registered** (no
  `xdg-mime default`, no `mimeapps.list` write).
- A task writing it to `~/.local/share/applications/` with mode 0644,
  skipped when `agentsview_install_desktop_appimage` is false.
- `update-desktop-database` after the write, so the launcher cache reflects
  it without a logout.
- `remove.yaml` deleting the file and re-running `update-desktop-database`.

Constraints:

- The `.desktop` may only be written when the AppImage exists — it is a
  launcher pointing at a specific file.
- `~/.agentsview` stays untouched by both directions.
- Do not register the scheme handler; carrying the declaration is deliberate.

Tests (in the harness from DOT-402.1): the rendered file passes
`desktop-file-validate`; a **separate** test asserts `Exec=` is absolute,
because a relative one is spec-valid yet broken; the MIME declaration
survives; install twice leaves exactly one file; remove deletes it; the
opt-out creates nothing. Skip with a named reason when
`desktop-file-validate` is absent.
<!-- SECTION:DESCRIPTION:END -->
