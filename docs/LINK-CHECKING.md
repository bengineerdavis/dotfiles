# Documentation link validation

Use Lychee to check documentation links. Keep local validation in the normal
edit and commit loop. Review external network access before it happens.

This document specifies the policy for a future implementation. It does not
install Lychee or authorize a new automated network call.

## Cadence

| Boundary | Scope | Network |
|---|---|---|
| Pre-commit | Changed Markdown files | None |
| Pre-push | All committed Markdown files | None by default; external check requires the review below |
| Before merge | All committed Markdown files | External HTTP(S) check after the author reviews that run |

The changed-file hook passes its filenames to Lychee. It must not silently
expand into a repository-wide scan. The full local pre-push scan must include
every committed Markdown document, including unchanged files.

Run the external check before merging changes that add or alter links. A
pre-push run is sufficient when it covers the exact commit range being pushed.
The merge gate must require evidence of that run rather than assume a previous
run covers a newer revision.

## Local configuration

The shared local configuration uses:

```toml
offline = true
include_fragments = "anchor-only"
include_mail = false
include_verbatim = false
insecure = false
```

The pre-commit invocation supplies the offline flag as well as the shared
configuration. This redundant boundary protects local commits if a future
configuration edit accidentally removes `offline = true`.

The input selector includes every committed Markdown file, with these explicit
exceptions:

- `.lore.md` — Lore owns this machine-managed memory; documentation tooling
  must not read, check, or rewrite it.
- `backlog/` — generated queue files are not authored documentation.
- `changelog.d/` — Scriv fragments are transient merge inputs.
- `CHANGELOG.md` — generated from those fragments.
- `home/dotfiles/apps/ollama/docs/` — explicitly research documents rather than
  maintained project documentation.
- `home/bin/executable_READMD.archive.md` and `home/bin/READMD.archive.md` —
  archived scripts, not documentation.

Do not add an undocumented exclusion merely to obtain a green check. Every
additional exception needs a stated reason and a review.

Local anchors are checked in documents maintained as Markdown. Lychee does not
run a browser engine, so it cannot prove anchors generated by JavaScript on an
external site. An external anchor failure needs a documented exception or a
corrected reference, not a claim that all external fragments were verified.

## External review before egress

The ethics layer forbids automated end-to-end egress and bypassing human review.
Therefore this policy does **not** install an unattended network-enabled
pre-push hook. The author must approve the external scan for a given revision,
or explicitly change that higher-level rule before such a hook is introduced.

The review covers the revision being checked and the fact that the checker will
visit its public documentation URLs. It is not a per-URL approval workflow. If
the documents contain work-tagged or other non-public material, do not run the
external scan; report that restriction and resolve it before proceeding.

After approval, run the full scan with:

```sh
lychee --config lychee.toml --offline=false --no-progress .
```

The implementation must use a fixed, reviewable command. It must not pass
repository file contents, credentials, or environment variables to remote
servers. Lychee sends requests to the extracted destinations; it does not
upload the documents themselves. Redirects are followed only under the private
network restrictions below.

## Network restrictions

The external configuration must retain:

```toml
exclude_private = true
exclude_loopback = true
exclude_link_local = true
exclude = ["(?i)^https?://localhost(?::[0-9]+)?(?:/|$)"]
insecure = false
require_https = true
```

Do not disable TLS verification. Do not add an include rule that overrides
private-network exclusions. `require_https` rejects plain HTTP references when
HTTPS is available; an HTTP-only public reference requires an individual,
explained exception.

Do not configure:

- `archive` or `suggest`, which can send broken-link data to an archive service;
- cookies, basic authentication, GitHub tokens, or custom headers;
- preprocessors, which would introduce a second command-execution surface;
- remote documents as checker inputs. All inputs are committed local files.

Use a request timeout and bounded concurrency. The implementation should record
its Lychee version and invocation in the PR evidence. Do not accept timeouts as
success by default. If a public host repeatedly rejects automated requests,
record an individual exclusion with the measured failure and a manually checked
result.

## Ownership and delivery

Install Lychee with mise using the `aqua:lycheeverse/lychee` backend. Pin the
version in the repository's mise configuration and record the tool and verified
reference version in `docs/REFERENCES.md`. Do not introduce a separate Brew,
Cargo, or unowned binary channel.

The implementation follows this policy in a separate PR. It adds the offline
pre-commit hook, the full local pre-push hook, the reviewed external-check
command, configuration, and focused tests for input selection and failure
handling. Prove the local check fails for a broken local link and that the
external command cannot silently become an unattended hook.

The documentation consolidation PR follows the tooling PR. It uses the new
checks to fix existing links and consolidate topic guidance without combining
that editorial work with security-policy changes.
